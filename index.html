    สิ่งที่ควรนำไปใช้ต่อ

    • Session ที่ปกติต้องพิสูจน์ได้ทั้ง 4 ช่วง
      ก่อน login, ตอน login, หลัง login และหลัง logout — cookie ที่ไม่มี HttpOnly/Secure หรือยังใช้ได้หลัง logout คือสัญญาณที่ต้องรายงาน
    • Hash ที่ดีเอาชนะรหัสผ่านที่แย่ไม่ได้เสมอไป
      Argon2/bcrypt ลด offline-cracking risk ได้มาก แต่รหัสผ่านซ้ำหรือคำที่พบใน breach list ยังเสี่ยงอยู่ดี
    • Control ต่อ brute force ต้องสมส่วน
      Lockout ที่ไวเกินไปกลายเป็นเครื่องมือ DoS ใส่ผู้ใช้จริง ส่วน rate-limit ที่หย่อนเกินไปปล่อยให้เดารหัสผ่านต่อได้เรื่อย ๆ
    • สังเกตตาม pattern ไม่ใช่แค่ตัวเลข threshold
      Password spraying กระจายไปหลายบัญชีบัญชีละไม่กี่ครั้งจะรอดจาก threshold รายบัญชี ต้องดูที่แหล่งที่มาด้วย

    ผลแต่ละภารกิจ

    คำศัพท์สำคัญของกิจกรรม
    Authentication
    กระบวนการพิสูจน์ว่าผู้ใช้เป็นใครหรือถือ credential ที่ถูกต้องหรือไม่
    Session
    สถานะที่ระบบจำไว้หลัง login เพื่อไม่ต้องส่ง credential ซ้ำทุก request มักอ้างอิงด้วย session cookie
    Salt
    ค่าสุ่มเฉพาะแต่ละบัญชีที่ผสมกับรหัสผ่านก่อน hash เพื่อกัน rainbow table และทำให้ hash ของรหัสผ่านเดียวกันไม่ซ้ำกันข้ามบัญชี
    Work factor / memory-hard hashing
    การออกแบบ hash ให้คำนวณช้าและ/หรือใช้หน่วยความจำมาก (เช่น bcrypt, Argon2) เพื่อให้ offline cracking ทำได้ช้าลงมาก
    Credential stuffing
    การใช้คู่ username/password ที่หลุดจากเว็บอื่นมาลองกับระบบเป้าหมาย โดยไม่ต้องเดาหรือ crack อะไรใหม่
    Password spraying
    การลองรหัสผ่านที่พบบ่อยเพียงไม่กี่ครั้งต่อบัญชี แต่กระจายไปหลายบัญชี เพื่อหลบ threshold ที่นับจากบัญชีเดียว
    Account lockout เป็น DoS vector
    นโยบาย lockout ที่ไวเกินไปเปิดช่องให้ผู้ไม่หวังดีล็อกบัญชีของผู้อื่นได้โดยไม่ต้องรู้รหัสผ่านจริง
